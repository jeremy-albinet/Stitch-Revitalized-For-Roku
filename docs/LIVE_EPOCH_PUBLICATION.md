# Validated live source boundaries

Status: publication, staged initialization pairs, segment association, protected assets and Server integration are implemented behind an explicit flag that defaults to false. The production Session does not enable it. Native source-boundary playback remains required before enablement.

The existing unversioned publication and its manifest output are preserved. A new exact `version=2` contract adds a stable local discontinuity sequence and each segment's local epoch plus complete initialization pair. Every segment retains its original media sequence, duration and media asset identities. Local epochs stay equal or advance exactly one; initialization changes require a boundary, and same-epoch initialization pairs are immutable.

Both audio and video manifests emit matching discontinuity sequences and boundaries with the correct initialization map. Once a boundary leaves a rolling window, the surviving first segment's stable epoch becomes its discontinuity sequence. Reused initialization assets must retain their original complete pair and track role; media collisions, incoherent pairs, malformed types, foreign sessions, unknown schemas and bounded timeline violations are rejected.

`loopbackPublicationAssets` returns all validated initialization/media identities and their tracks, deduplicated under the existing asset bound. This metadata helper does not approve downloaded bytes or a decoder. Core stages and atomically admits complete initialization pairs after actual downloaded-byte and native decoder approval, preserves shared identities and epoch labels across generations, and retains advertised/requested assets through their lease/grace lifecycle. Server validates both tracks' later initialization maps and complete media bodies without weakening ownership or transport limits. Later initialization must remain within the immutable first master codec envelope.

This capability preserves ads and timestamps. It does not normalize a genuine source discontinuity, skip advertising, increase recovery budgets, change default playback eligibility or establish native decoder continuity. Recent device diagnostics showed real new map/epoch boundaries and no nonzero epoch offset on immutable overlapping segments. Fresh native ad-boundary, return-to-content, synchronized audio/video, retention, sustained playback and clock tests remain open.

Actual BrightScript regressions cover content/ad/content, short consecutive boundaries, rolling windows, both-track map/discontinuity parity, complete initialization reuse, integer endpoints and unchanged legacy byte goldens. Strict malformed publications and normally exiting production mutations are rejected. The contract follows [HLS discontinuity and rolling-playlist requirements](https://www.rfc-editor.org/rfc/rfc8216.html).

The combined fixture executes actual Core, Fetch, initialization gate, publication and Server functions, including later-map HTTP ranges, held leases and cleanup. Its 620 assertions and four guard-removal mutations pass; network delivery, native decoder decisions and clocks are fixture boundaries. All nine offline suites and 79 Node tests pass. A private native run stopped at the unchanged master compatibility check before admitting a new pair. A separate five-minute run completed but encountered no source boundary. Neither run establishes successful native transitions; detailed evidence remains in [device verification](DEVICE_VERIFICATION.md).
